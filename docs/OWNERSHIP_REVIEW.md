# 对外展示前的来源核验

## 当前结论

原始工作目录的 `blade-sypay` 模块包含 SpringBlade 与 JeePay 的版权头和既有支付通道代码。现阶段无法仅根据文件存在判断每一行的原创归属，因此不将该源码整体复制到本面试仓库。

## 可以安全展示的内容

- 需求拆解、模块设计、接口链路和运行环境搭建过程。
- 你亲自完成且能讲清楚的页面、接口、数据库表、配置或测试改动。
- 在保留上游 LICENSE、NOTICE 和版权头前提下的独立补丁。

## 不应直接展示或宣称的内容

- 上游框架的完整源码。
- 已存在的多支付渠道、退款、分账、转账等实现，除非能提供你的独立提交或补丁证据。
- 未打包、未部署、未联调通过的服务，不能描述为“生产可用”。

## 补齐为可演示代码仓库的步骤

1. 以 SpringBlade 上游版本建立 fork，并保留原始 LICENSE/NOTICE。
2. 使用 Git 提交或补丁记录你自己的控制器、页面、SQL、配置和测试修改。
3. 添加脱敏的 `application-example.yml`、建表脚本和启动说明。
4. 用 Nacos、Redis、MySQL 和支付宝沙箱完成一次从登录到统一下单的录屏或测试记录。
5. 对外仅描述验证过的商户管理、配置管理和沙箱支付链路。
