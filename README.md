# 聚合支付后台管理系统

面向商户的聚合支付后台管理系统，提供商户、商户应用、支付方式、支付接口和支付配置等统一管理能力，并支持在支付宝沙箱环境完成下单支付流程。

## 项目用途

商户通常需要分别对接支付宝、微信等不同支付渠道，接入与维护成本较高。本项目为商户提供统一的支付管理入口：管理员可维护商户及其业务应用，配置可用的支付方式和支付接口；商户发起支付时，系统根据支付信息选择对应渠道，创建订单并调用渠道接口返回支付结果。

当前项目完成支付宝沙箱支付链路，用于验证从商户与应用配置、支付接口配置到统一下单和订单结果处理的完整流程。退款、分账、转账及其他真实支付渠道不属于本项目当前实现范围。

```text
商户与应用配置 → 支付方式及接口配置 → 发起支付 → 创建订单 → 调用支付宝沙箱 → 返回结果并更新订单状态
```

## 功能模块

- 商户管理：商户信息查询、新增、编辑、删除和批量删除。
- 商户应用：维护商户应用信息；新增商户时自动创建默认应用，删除商户时同步处理关联应用。
- 支付方式管理：配置支付方式及其展示信息，支持图片上传。
- 支付接口管理：维护支付接口定义和商户支付接口配置。
- 商户中心：根据登录身份隔离商户应用与配置信息。
- 统一下单：根据支付条码识别支付渠道，读取商户与支付配置，创建订单并调用支付渠道。

## 技术栈

- 后端：Java 8、Spring Boot、Spring Cloud、SpringBlade、MyBatis-Plus、Nacos、Redis
- 前端：Vue 2、Element UI、Axios
- 数据库：MySQL
- 第三方能力：阿里云 OSS、支付宝沙箱

## 系统结构

```text
Saber 管理端
    ↓
Spring Cloud Gateway
    ↓
认证、用户、系统、聚合支付等服务
    ↓
MySQL / Redis / Nacos / OSS / 支付渠道
```

## 核心流程

1. 管理员维护商户、商户应用、支付方式和支付接口配置。
2. 商户发起支付时，系统根据条码识别支付渠道并校验渠道可用性。
3. 系统加载商户应用及接口配置，创建支付订单并调用对应支付渠道。
4. 系统处理渠道返回结果，更新订单状态并返回统一响应。

## 本地启动

1. 启动 MySQL、Redis 和 Nacos。
2. 导入 SpringBlade 基础表与支付业务表，配置 Nacos 中的数据库、Redis 和应用参数。
3. 启动认证、网关、用户、系统和聚合支付服务。
4. 启动前端项目，通过网关访问管理端。
5. 在支付配置中填写支付宝沙箱参数，使用商户应用发起支付测试。
